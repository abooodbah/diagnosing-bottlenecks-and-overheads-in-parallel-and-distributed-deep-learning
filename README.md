# Where the cost lands: sharding and expert-routing measurements

Measurement artifact for the case studies in Section 9 of the survey
"Diagnosing Bottlenecks and Overheads in Parallel and Distributed Deep
Learning" and for the companion technical report of the same name. The
repository holds the complete harness, raw per-run records, processed
tables, figures, transport diagnostics, and environment snapshots for the
ZeRO sharding and mixture-of-experts routing experiments.

## What was measured

A 2.547-billion-parameter decoder-only transformer (30 layers, hidden
dimension 2560, 20 attention heads, SwiGLU intermediate dimension 6912,
sequence length 2048, BF16 with FP32 master state) trains under DeepSpeed
stage 0 (replicated DDP), ZeRO-2, and ZeRO-3 at one, two, and four nodes on
two platforms, three repetitions per cell:

- **Intel Max 1550:** 8 tiles per node (8, 16, 32 ranks), oneCCL over a
  host-staged OFI/TCP path.
- **NVIDIA H100:** 4 GPUs per node (4, 8, 16 ranks), NVLink inside the
  node, host-staged NCCL over InfiniBand between nodes, plus a TCP-socket
  control at two nodes.

A separate microbenchmark measures expert-parallel all-to-all under
balanced routing and under routing 50% of tokens to one expert, with one
SwiGLU expert per rank and 4096 tokens per rank.

Communication overlap is disabled and every collective is wrapped with
device-synchronized timers at both the torch.distributed and framework
layers, so each recorded phase is an exposed cost. Step time is the
maximum across ranks; reported values are medians of three repetitions.

## Findings the data supports

- **ZeRO-2:** peak memory falls 3.4x to 4.1x on both platforms, and the
  four-node step-time price of the introduced collectives is set by the
  communication path: +11.9% over host-staged InfiniBand against +107.9%
  over host-staged TCP.
- **ZeRO-3:** the exposed step stays between 18.3 s and 19.2 s from one
  node (NVLink only) to four nodes, with 98% to 99% of the step attributed
  to roughly 206 serialized layer-wise all-gathers per iteration.
  Replacing InfiniBand with TCP sockets at two nodes moves the step only
  11.9%, so transport bandwidth is secondary in this configuration.
- **Expert routing:** the same 50% skew cuts the Intel step from 434 ms to
  171 ms by relieving endpoint contention, and raises the H100 step from
  15.6 ms to 28.6 ms by putting the overloaded expert on the critical
  path.

## Claim boundaries

- All multi-node communication is host-staged. GPUDirect RDMA faulted on
  the measured H100 node image (`IBV_WC_LOC_PROT_ERR` on GPU-memory
  sends); the fault evidence is in `transport_logs/`.
- The measurements characterize exposed per-step cost under disabled
  overlap, not production throughput, convergence, or accuracy.
- The two platforms run different ranks per node (8 against 4) and
  different runtime stacks; scaling shapes are comparable, absolute rates
  and vendors are not.

## Layout

- `harness/` benchmark programs (`llama_bench.py`, `moe_bench.py`), the
  per-rank environment shim, and the Slurm launch scripts. Model and
  runtime configuration live in the benchmark programs and are echoed into
  every result record.
- `raw/h100/`, `raw/pvc/` one JSON per run: step-time percentiles, peak
  memory, per-rank barrier waits, and per-operation communication totals.
- `processed/summary.csv` per-cell medians and the exposed-cost
  decomposition, generated by `scripts/analyze.py`.
- `figures/` the three rendered figures.
- `scripts/analyze.py` reads `raw/`, writes `processed/` and `figures/`.
- `transport_logs/` Slurm job logs, including the GPUDirect fault evidence
  and the diagnostic sequence that qualified the Intel path.
- `environment/` pip freezes for both platform environments and the module
  and environment-variable configuration.
- `artifact_manifest.csv` maps each reported claim to its raw files, the
  processing script, and the figure or table that shows it.
- `checksums.txt` SHA-256 checksums for raw, processed, and figure files.

## Reproducing the figures and tables

Python 3.10 or newer with matplotlib is sufficient for analysis; no
accelerator is needed.

```bash
python scripts/analyze.py
```

This regenerates `processed/summary.csv` and all three figures from
`raw/`. `scripts/reproduce_all.sh` runs the same step and verifies the
checksums.

Re-running the measurements requires a Slurm cluster with the matching
accelerators. Set `ZMIG_ROOT` to a working directory containing `harness/`
and `ZMIG_VENV` to a Python environment matching `environment/`, then
submit `harness/launch/zmig_pvc.slurm` or `harness/launch/zmig_h100.slurm`
with `sbatch -N <nodes> -t <time>`. The header of the PVC script records
the environment constraints the Intel path requires.

## Environment

- H100: PyTorch 2.11.0+cu128, DeepSpeed 0.19.4, CUDA 12.8 runtime,
  Python 3.12.
- Intel Max 1550: PyTorch with Intel extension and oneCCL bindings,
  DeepSpeed 0.19.4, Python 3.12.

Full package lists are in `environment/`.
